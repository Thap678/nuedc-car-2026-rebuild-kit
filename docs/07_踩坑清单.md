# 07 踩坑清单（按症状查）

| 症状 | 原因 | 处理 |
|---|---|---|
| 写命令返回 `connector did not respond` / 空 JSON | 连接器在负载下「假失败」，写入可能已经生效 | 先读回（`sch list` / `pcb list` / 存盘文件）再决定是否重试；`common.run` 已带重试 |
| 写命令返回 ok，读回没变化 | 「假成功」（CLI 有时会提示 `fakeSuccesses`） | 一律以读回为准；摆放脚本都在最后统一读回核对 |
| `pcb modify` 同时改 `layer` 和 x/y 没生效 | 带 `layer` 的补丁和坐标一起发会被静默丢弃 | 先单独发 `{"layer": 2}`（数字，不是 "BOTTOM"），再发坐标 |
| `sch list` 读回的 `pin.net` 是空的 | 部分工程的接口回读不可靠 | 用 `verify_file.py` 读存盘的 .esch2 |
| 放置某个器件一直超时 | 用了符号 UUID 而不是器件 UUID | `easyeda lib search` 结果里的 `uuid` 才是器件 |
| `easyeda health` 里 `windows: []` | EDA 没开或扩展没连上 | 打开 EDA 和工程；重载 easyeda-agent 扩展；daemon 要先起 |
| EDA 断开后窗口 ID 变了 | 重连会换 windowId | 用 `--project` 路由；`project export` 这类必须带 `--window` 的命令现查（`common.window_id()`） |
| `project export` 报 `explicit --window and --project-uuid are required` | 该命令必须显式给窗口 | `kit/backup.py` 已处理 |
| Freerouting 全部版本都剩十几条布不通 | ① 输入里焊盘重叠（日志 `pre-existing clearance violation`）；② 预处理把排针焊盘误放大 | ① 回布局查封装；② 对比原始导出与 prep 后的焊盘尺寸 |
| 库里同一料号的封装变了 | 嘉立创库更新 | 布线前核对密集处焊盘；必要时换器件（示例换成系统库 Test-Point-0.5mm） |
| 导入 SES 后 DRC 报线宽/间距 | EDA 导入时把线宽改成网络规则默认值 | `apply_ses.py` 会恢复成布线时的宽度（且不低于规则最小值） |
| 导入后 5V 粗线贴着别的过孔报间距 | 布线间距（0.2）低于该类规则要求（0.25） | 给该类单独提高间距，或把那一两段短线收窄（不低于规则最小值） |
| 后处理后某个网络断开 | 早期版本成股时挪动了 T 型接点 | 已修；导入前跑 `ses_conn.py`，导入后跑 `conn.py` |
| 缝合孔贴着排针焊盘，DRC 报 TH Pad to Via / Hole to Hole | 早期版本缝合不避让焊盘 | 已修（通孔焊盘留 0.55 mm）；仍有个别时 `pcb via-delete` |
| 过孔吸附网格后 DRC 报 Hole to Hole | 吸附把两个孔拉得太近 | 已加孔距 ≥ 0.8 mm 约束 |
| `stitch` 计划坐标放到板外 | 计划文件单位是 mm 还是 mil 弄混 | `stitch.py` 规划和放置合在一起，内部统一换算 |
| `restore-copper` 报「restored」，DRC 却报某根电源线断开 | `guard.py` 的 canon 把近零长线段并进了相邻的横竖两段，漏画一整段 | 已修（近零长线段不参与合并）；每次 restore 后跑 `kit/pcb/cover_check.py target.json after.json` |
| GND 焊盘四周有铺铜，DRC 还报 disconnected | 铺铜用花焊盘连接，焊盘被走线围住放不下辐条 | 铺铜规则改直连（`connectMode` 1），见 05 第 7 节 |
| `pcb drc` 超时，之后 EDA 卡住 | EDA 窗口在后台时画布重算不跑；每次重试再叠一轮重算 | 窗口放前台再跑，只跑一次 |
| `conn.py` 报某信号网断开，DRC 不报 | `conn.py` 只认端点相接，线接在另一根线中段（T 形）被当成断开 | 以 `ses_check.py` / DRC 为准 |
| GND 扇出孔 DRC 报 Hole to Hole | 同网孔贴着同网通孔焊盘：铜间距不查，孔距要查 | `route_bundle.py` / `gnd_tie.py` 已避让通孔焊盘 |
| DSN 导出在哪 | 在执行命令时所在目录的 `.easyeda/artifacts/` 下 | 命令输出里有完整路径 |
| msiexec 解包 Freerouting 报 1603/1708 | 目标路径有中文 | 解到 `C:\fr_extract` 这类纯英文路径 |
| freerouting-cli（原生版）崩溃 | 原生版遇到禁布区/多轮之间会崩 | 用 Java 版 freerouting.exe |
| Freerouting 优化阶段超时、结果没存盘 | 优化很慢，超时直接丢结果 | `--router.optimizer.enabled=false`（route.py 默认） |
| `drv.py connect` 报 `pin already connected to net "$1N.."`，`--replace` 也报 `stub touches an existing (foreign-net) wire` | 第一次连线时标签没放上，只留下一段没有网络名的短线，挡住了这个脚 | `python kit/sch/fix_pin.py <页.json> <位号> <脚号>`：删掉这段无名短线并重连，然后重跑核对 |
| `easyeda project create` 建出来的是 `.eprj2`（单文件数据库），文件夹里找不到 `.esch2` | CLI 新建的是数据库工程；`.eprj2` 里的页面数据是加密的，读不出来 | 不影响：`build_pages.py` 会导出 `.epro2` 再从里面切出页面核对。想要文件夹工程（.eprj3）就在 EDA 界面里新建 |
| 从 `.epro2` 切出的页面核对时几乎所有脚都「got nothing」 | 导出文件里 y 坐标是负的（文件 y = −接口 y），文件夹工程的 `.esch2` 是正的 | `verify_file.py` 已自动判断方向 |
| `AMBIGUOUS_WINDOW: 2 connector windows are connected` | 同时开着两个 EDA 窗口 | 命令加 `--project <工程 UUID>`；需要 `--window` 的命令用 `common.window_id(project)` 按工程挑窗口 |
| 出板导出报 `路径不允许` / `非全离线客户端环境无法调用本接口` | `eda.sys_FileSystem` 写盘接口限制路径，非全离线客户端直接禁用 | `kit/fab/export.py` 已改成 base64 传回、由 Python 写盘 |
| `project open` 返回 `Official openProject returned false` | 官方打开工程接口偶尔失败；窗口可能已经关掉了原工程 | 不要反复重试；在 EDA 界面里手动打开工程，再用 `easyeda health` 确认 |
| `gmetrics.py` 报很多「死铜」，但 EDA 的「保留孤岛」是关的 | 评分脚本把焊盘近似成圆，不规则焊盘的边角接触不到，会把实际接地的铺铜算成死铜 | 只影响评分不影响出板；以 EDA 的 DRC 和 `conn.py` 为准 |
| 同一个工程，换一种方式打开后 `easyeda health` 报的工程 UUID 变了 | EDA 按工程文件夹路径登记 UUID；文件夹被删后在原路径重建的工程，重新打开时会沿用旧路径登记的 UUID | **board.toml 的 `project` 以 `easyeda health` 当前显示的为准**；`tools/check_env.py` 会报 `config project is open` FAIL。PCB 和页面 UUID 不变 |
| `pcb auto-place` 之后 `layout-lint` 报短路/重叠/出界，飞线交叉变多 | 自动摆放的打包不保证合法（issue #6） | `python kit/pcb/guard.py place auto-place`：自动挪回、必要时整体撤销；已经坏了用 `place_from_dump.py <快照>` |
| `pcb route-short` 后 DRC 一堆 `distance is 0mil`，Freerouting 报 pre-existing | L 形走线压到异网焊盘、线宽不按网络规则（issue #5） | `pcb rip-up --net <这些网络>`；以后用 `guard.py route-short`（离线丢掉不合法的跳线，画完再 DRC 修剪） |
| `pcb beautify` 返回 `context deadline exceeded`，DRC 上百个 Connection Error | 整板一次调用超时，已删了一部分线（issue #4） | `python kit/pcb/guard.py restore-copper <之前的 dump>`（没有快照就拆线重导 SES）；以后用 `guard.py beautify` 分批跑 |
| 读回核对说「缺两段、多一段」，但板上看是好的 | EDA 把连续创建的共线同网走线合成了一段 | 按合并后的几何比较（`guard.py` 的 `canon()`）；不要把合并后的那段当「多余」删掉 |
| 新画的线 DRC 报和 GND 铺铜 0 mil，但已经 `pour-rebuild` 过 | 铺铜在 `doc reload` 之后回到旧的 | reload 之后再 `pour-rebuild`、再 DRC；或者 rebuild 后直接 DRC |
| `doc reload` 后所有命令都报 `--doc guard: no connected window`，`easyeda health` 里 documentType 是 null | reload 关掉了 PCB，重开超时（连接器 DEGRADED） | 在 EDA 里手动点开 PCB 标签页；能不 reload 就不 reload |
| 导入 SES 后 DRC 报几十上百个 `inner diameter of the via hole ... is 7.8mil` | EDA 导入 Freerouting 的 17.7 mil 过孔时孔径给 7.8 mil，比 0.2 mm 规则小一点 | `python kit/route/fix_vias.py --apply`；EDA 会把 7.9 存成 8，脚本已按「不小于目标」读回 |
| 重新布线后过孔贴着别的线/焊盘，但 Freerouting 报 0 violations | DSN 从已布线的板导出，`(via via0 via1 via2)` 给了多种过孔，Freerouting 放过孔时不守间距 | `prep_dsn.py` 已只保留规则尺寸那一种；旧的 prep 文件要重新生成 |
| 工作文件夹被误删 | 没有异地备份 | 见 docs/08；以后每个阶段 `kit/backup.py` |
